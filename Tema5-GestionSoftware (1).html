Práctica 05 · Administración Linux · Preguntas de tus tests explicadas en sencillo

1. Conceptos básicos

  • Paquete: colección de archivos que se instalan juntos (programa, configuración…). Incluye reglas: dependencias, preinstalación y postinstalación.
  • Dependencias: otros paquetes que deben estar instalados para que un programa funcione. Si faltan, el sistema avisa (o las instala). Tampoco deja borrar un paquete que otro necesita. Si es un lío, se llama «infierno de las dependencias».
  • Sistema de paquetes: el mecanismo que lleva la cuenta de todos los archivos instalados, el paquete al que pertenecen y el directorio donde están.
  • Base de datos de archivos instalados: cada fichero instalado, el nombre de su paquete e información adicional.
  • Checksum: número calculado a partir de un archivo; si el archivo se daña o cambia, ya no coincide. No se comprueba solo: dpkg -V.
  • Depósito (repositorio): catálogo de paquetes instalables, en un servidor de confianza (también CD/DVD). Permite descargar los paquetes. Lo gestiona el sistema de paquetes, no el administrador a mano.

4. Línea de sources.list

deb http://es.archive.ubuntu.com/ubuntu/ precise main restricted

  1. deb = paquetes binarios (deb-src = código fuente)
  2. URL del depósito
  3. distribución (precise, noble…)
  4. categorías (main restricted…)

Archivo: /etc/apt/sources.list y /etc/apt/sources.list.d/. En Ubuntu 24.04+ se usa el formato nuevo .sources (campos Types, URIs, Suites, Components).

5. apt y dpkg

  • dpkg: trabaja con archivos .deb locales; no descarga ni resuelve dependencias.
  • apt / apt-get: usa dpkg por debajo, descarga desde los depósitos e instala las dependencias.

7. Estado en dpkg -l (tres letras)

1ª = deseado · 2ª = actual · 3ª = error (normalmente vacío).

  • Deseado: i instalar · r eliminar (sin config) · p purgar (todo) · h retener · u desconocido
  • Actual: i instalado · c solo config · n no instalado · U desempaquetado · F/H a medias
  • Error: R hay que reinstalar

ii = debe estar instalado y lo está. rc = se quitó el programa pero quedan sus archivos de configuración.

8. Nombre de un paquete .deb

nombre_versión-revisión_arquitectura.deb. Ej.: zsh_5.9-6ubuntu2_amd64.deb → paquete zsh, versión 5.9, revisión 6 de Debian, 2ª modificación de Ubuntu, arquitectura amd64.

9. Ciclo completo (ejemplo zsh)

  1. dpkg -l zsh: ¿está instalado?
  2. sudo apt-get install zsh
  3. dpkg -l zsh: estado ii
  4. dpkg -L zsh y ls -al /bin/zsh*: qué archivos hay
  5. sudo apt-get remove zsh → dpkg -l zsh da rc
  6. sudo apt purge zsh: borra también la configuración

10. Ojo: cosas que han cambiado

Los tests usan ejemplos de Ubuntu 12.04 («precise»), pero los conceptos son los mismos. En Ubuntu 24.04 las fuentes están en ubuntu.sources; en 26.04 existen APT 3 y sudo-rs, y neofetch se sustituye por fastfetch.
